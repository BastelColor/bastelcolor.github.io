# コンテンツの足し方

サイトに載せる文章・画像・モデルを、自分で足したり直したりするためのガイドです。
**文章やリンクは `content/` の中のファイル、画像やモデルは `public/` の中に置きます。**
画面の作りやデザインのコード（`components/`、`app/`）は、ふだん触らなくて大丈夫です。

> このガイドは、サイトの仕組みが変わったら一緒に更新しています。
> ここに書いてある手順で足せないものがあれば、それは仕組みの追加が必要なものです。

## 1. 確認のしかた

```bash
npm run dev
```

ブラウザで http://localhost:3000 を開きます。ファイルを保存すると、画面も自動で更新されます。

公開する前に、エラーがないかを次のコマンドで確認します。

```bash
npm run build
```

`✓ built in ...` と `Prerendered ... routes` が出れば大丈夫です。エラーが出たら [困ったとき](#11-困ったとき) を見てください。

### 公開のしかた

GitHub の `BastelColor/bastelcolor.github.io` の `main` ブランチに push すると、自動でビルドされて数分後に https://bastelcolor.github.io/ に反映されます（`.github/workflows/deploy.yml`）。
進み具合とエラーは、GitHub のリポジトリの「Actions」タブで見られます。

- サイトは全部、静的なファイルとして書き出しています（`next.config.ts` の `output: 'export'`）。サーバーは使っていないので、公開の費用はかかりません。
- 前のホームページ（https://bastelcolor.github.io/homepage/ ）は、別のリポジトリ（`BastelColor/homepage`）のまま残ります。

## 2. ファイルの書き方の基本

`content/` のファイルは TypeScript ですが、足すときは **既にある項目をコピーして書き換える** のがいちばん確実です。

```ts
{
  title: 'SimpleApartment',      // 文字は ' ' で囲む
  year: '2024',                  // 数字っぽくても ' ' で囲む
  body: ['1段落目', '2段落目'],   // 複数あるものは [ ] で囲んで , で区切る
},                               // 項目どうしの間にも , が必要
```

- 文字の中で `'` を使いたいときは `\'` と書きます（例: `'Let\'s go'`）。
- 項目と項目の間の `,` を忘れるとエラーになります。最後の項目のうしろの `,` は、あってもなくても大丈夫です。迷ったら、すべての行の最後に付けておけば確実です。
- 各項目の意味は `content/types.ts` にもコメントで書いてあります。
- VS Code で開くと、書き間違いに赤い波線が出ます。

## 3. サイト名・役職

**ファイル:** `content/site.ts`

| 項目 | 内容 |
|---|---|
| `title` | ブラウザのタブや検索結果に出るサイト名 |
| `description` | 検索結果やリンクの共有時に出る説明文 |
| `url` | 公開しているURL。SNSで共有したときのカードに使います（URLが変わったときだけ書き換えます） |
| `roles` | トップの名前の下に出る役職。`/` で区切って表示されます |
| `googleSiteVerification` | Google Search Console の持ち主の確認用の文字（下の「Google に登録する」）。空なら何も出しません |
| `goatcounter` | アクセス数を数える GoatCounter のコード（下の「アクセス数を見る」）。空なら数えません |

トップの大きな「Yzmo」と「唯繕物置」の文字は、デザインの一部としてコードに直接書いてあります。

### タブのアイコン

`public/` の次の3つです。差し替えるときは、同じ名前・同じ大きさの画像で上書きします（Claude に元の画像を渡せば作れます）。

| ファイル | 大きさ | 使われる場所 |
|---|---|---|
| `favicon.ico` | 16・32・48px 入り | ブラウザのタブ |
| `icon.png` | 192×192 | ブラウザのタブ（高解像度の画面） |
| `apple-touch-icon.png` | 180×180、背景は白 | iPhone のホーム画面に追加したとき |

### 共有したときのカードの画像

X や Discord などに URL を貼ったときに出る画像は `public/og.png`（1200×630）です。いまはトップのページをそのまま撮った画像です。差し替えるときは、同じ名前・同じ大きさの画像で上書きします。

- ブログの記事は、その記事の `thumbnail` がカードの画像になります。`thumbnail` が無い記事は `og.png` が使われます。
- X などは画像を覚えておくので、差し替えてもしばらく前の画像が出ることがあります。

### 検索エンジン向けの一覧（自動）

公開するたびに、`sitemap.xml`（サイトにあるページの一覧）と `robots.txt` が自動で作られます。記事を足せば一覧にも自動で入るので、ふだんは何もしなくて大丈夫です（下書きの記事は入りません）。

### Google に登録する（Search Console）

Google にサイトを知らせて、検索でどう見つけられているかを見られるようにします。最初に一度だけやります。

1. [Google Search Console](https://search.google.com/search-console) を開き、「プロパティを追加」→ 右側の **「URL プレフィックス」** に `https://bastelcolor.github.io/` を入れます。
2. 確認方法の一覧から **「HTML タグ」** を選びます。`<meta name="google-site-verification" content="…" />` と出るので、`content="…"` の **…の部分だけ** をコピーします。
3. `content/site.ts` の `googleSiteVerification: ''` の `''` の中に貼り、公開します（Claude に渡して「入れて公開して」でも大丈夫です）。
4. 公開が終わったら（数分）、Search Console に戻って **「確認」** を押します。
5. 左のメニューの **「サイトマップ」** で `sitemap.xml` と入れて「送信」します。

検索結果に出るまでは、数日〜数週間かかります。`googleSiteVerification` は、確認が終わったあとも消さずに残しておきます（消すと持ち主の確認が外れます）。

### アクセス数を見る（GoatCounter）

[GoatCounter](https://www.goatcounter.com) という、Cookie を使わない無料のアクセス解析を使います。Cookie を使わないので、「Cookie に同意しますか？」の表示は要りません。

1. GoatCounter のサイトで「Sign up」からアカウントを作ります。**Code** の欄に入れた文字（例：`yzmo`）が、見るページの住所（`https://yzmo.goatcounter.com`）になります。
2. その Code を `content/site.ts` の `goatcounter: ''` の `''` の中に入れて、公開します。
3. `https://<Code>.goatcounter.com` を開くと、見られたページの数が出ます。

- 部屋は `/#works` のように、アバターは `/avatar/quiple`、作品は `/work/…`、記事は `/blog/…` として数えます。開いてすぐ（1秒以内）別の画面へ移ったものは数えません。
- 自分のパソコンで確認しているとき（`localhost`）は数えません。公開しているサイトを自分で見た分は数えられるので、気になるときは GoatCounter の設定（Settings）で自分を除外できます。

### ブログの更新情報（RSS・自動）

公開するたびに、ブログの更新情報 `feed.xml`（RSS）が自動で作られます。RSS リーダーに `https://bastelcolor.github.io/feed.xml` を登録すると、新しい記事が届きます。ブログの部屋のいちばん下にもリンクがあります。下書きの記事は入りません。

### フォント（自動）

文字のフォント（Zen Maru Gothic・Cherry Bomb One）は `fonts/` に入っています。公開するときに、サイトで使っている文字だけを取り出した軽いフォントが自動で作られるので、文章を足しても何もしなくて大丈夫です。`npm run dev` で確認しているときは、全部の文字が入ったフォントが使われます。

### ページがみつかりません（404）

存在しない URL を開いたときのページです。文字を変えるときは次のファイルを書き換えます。

| 変えたいもの | ファイル |
|---|---|
| ふわふわ浮かぶ「みつかりません」の文字 | `app/not-found.tsx` の `LETTERS`（1文字ずつ `' '` で囲んで並べる） |
| その下の説明文・雲のボタンの文字 | `components/not-found-back.tsx` |

前のホームページの URL（`/homepage/...`）から来た人には、説明文が「こちらのページは公開を終了しました！」に変わります。

## 4. トップの雲と部屋の見出し

**ファイル:** `content/pages.ts`

4つの雲（プロフィール・さくひん・アバター・ブログ）の設定です。

| 項目 | 内容 |
|---|---|
| `menuLabel` | 雲の文字と、部屋を開いたときの大きな見出し |
| `note` | 部屋の見出しの下の一言 |
| `tone` | 色（`pink` / `mint` / `blue` / `yellow`） |
| `mascot` | 雲のうしろから顔を出すキャラクター → [9. キャラクター画像](#9-キャラクター画像雲のうしろ部屋のすみ) |

- 雲の並び順は、このファイルに書いた順です。
- 「Yzmo」の4文字は、雲と同じ順番・同じ色で塗られます。並びや色を変えると、文字の色も一緒に変わります。
- 雲（部屋）そのものを増やす・減らすときは、仕組みの追加が必要です。

---

### 背景でふわふわ浮かぶ小物

トップと部屋の背景に浮かんでいる星・しずく・ハート・まるは、`components/floating-bits.tsx` の `HOME_BITS`（トップ）と `ROOM_BITS`（部屋）で決めています。

| 項目 | 内容 |
|---|---|
| `shape` | 形（`'star'` / `'drop'` / `'heart'` / `'dot'`） |
| `x`, `y` | 画面の左上からの位置（%） |
| `size` | 大きさ（px）。広い画面では自動で少し大きくなります |
| `tone` | 色（トップだけ。`pink` / `mint` / `blue` / `yellow`）。部屋の中では部屋の色になります |
| `duration`, `delay` | 浮き沈み1回の秒数と、始まるタイミングのずれ（マイナスの秒数） |
| `wideOnly` | `true` にすると、スマホなど細い画面では出しません |

## 5. プロフィール

**ファイル:** `content/profile.ts`

| 項目 | 内容 |
|---|---|
| `leadLines` | 大きく出る紹介文。1要素が1行になります |
| `body` | その下の説明文 |
| `skills` | 「つかっているもの」。`{ level: 'メイン', items: ['Blender', 'Unity'] }` のまとまりを、慣れている順に並べます。1まとまりが1行になり、`level` が行の頭の小さなラベル、`items` が `、` 区切りで並びます |
| `certifications` | 「資格」に1つずつ1行で並びます。`[]`（空）にすると「資格」の行ごと出なくなります |
| `links` | 「ほかの場所」に並ぶリンク。`{ label: '表示名', url: 'https://...' }` |

## 6. さくひん

**ファイル:** `content/works.ts`
**画像の置き場所:** `public/works/<作品のid>/`

### 作品を足す

`works` の中に1件ぶん足します。**書いた順に並びます。**

```ts
{
  id: 'simple-apartment',                         // 必須。英小文字・数字・ハイフン
  genre: 'vr',                                    // 必須。ジャンル（下の表）
  title: 'SimpleApartment',                       // 必須
  category: '3DCG / WORLD',                       // 必須。小さく出る分類
  description: 'VRChat向けワールド制作',             // 必須。一覧の下には出ず、詳細の冒頭に出る一言
  thumbnail: '/works/simple-apartment/thumb.webp', // サムネイル
  year: '2024',                                   // 制作年
  body: ['1段落目', '2段落目'],                      // 詳細の本文
  cover: '/works/simple-apartment/cover.webp',    // 詳細のいちばん上に、サムネイルと別の絵を出す
  youtubeId: 'dQw4w9WgXcQ',                       // 詳細のいちばん上に動画を埋め込む（cover より優先）
  images: [
    { src: '/works/simple-apartment/01.webp', alt: '室内の様子' },
  ],
  links: [
    { label: 'BOOTHで見る', url: 'https://booth.pm/ja/items/...' },
  ],
},
```

`thumbnail` から下は省略できます。**書いた項目だけが詳細に表示されます。**

### 作品のURL

作品を開くと、URL が `https://bastelcolor.github.io/work/<作品のid>` に変わります（例: `/work/toon-shader`）。この URL を共有すると、開いた人にもその作品の詳細が開きます。X などに貼ったときのカードには、その作品のタイトル・`description`・サムネイルが出ます（サムネイルが無い作品はサイト共通の画像）。

- 作品のページは、公開するときに `works` の中身から自動で作られます。

- `id` を変えると URL も変わるので、一度共有した作品の `id` はなるべく変えないでください。
- 前の形の URL（`/#works/toon-shader`）で来た人にも、同じ作品が開きます。
- 部屋だけの URL もあります: `#profile`（プロフィール）、`#works`（さくひん）、`#avatar`（アバター）、`#log`（ブログ）。
- ブログの本文から部屋へリンクするときは `[さくひん](/#works)` のように書きます。

### ジャンル（`genre`）

| 書く値 | 表示 |
|---|---|
| `'game'` | ゲーム |
| `'movie'` | 映像・画像（静止画の3DCGもここ） |
| `'book'` | 書籍/同人誌 |
| `'vr'` | VR |
| `'tool'` | ツール |

- 表示名や並び順は、同じファイルの `workGenres` で変えられます。
- ジャンルを **増やす** ときは、`content/types.ts` の `WorkGenre` にも同じ値を足します（例: `| 'music'`）。

### 画像

詳細のいちばん上には「動画（`youtubeId`）→ `cover` → サムネイル」の順に、あるものが1つ大きく出ます。
一覧ではアバターのスクショ、開いたら全員の集合絵、のように見せ分けたいときは `cover` を使います（例: 歴代キャラクター）。`cover` は縦横比そのままで表示されます。

ポートフォリオのスライドはそのまま載せず、元の画像・PSD のレイヤー・VRChat のスクショなど、素材そのものを使っています。

| 用途 | おすすめのサイズ | 備考 |
|---|---|---|
| サムネイル（`thumbnail`） | 横長 16:10（例: 1280×800） | 一覧では16:10で切り抜かれます。詳細では画面の幅いっぱいに大きく出ます |
| 詳細の画像（`images`） | 横幅 1600px くらいまで | 1列で幅いっぱいに出るので、ポートフォリオのスライドのような文字の多い画像も読めます。縦長の画像は画面の高さに収まるよう縮みます |

- 形式は WebP がおすすめですが、JPEG・PNG でも表示できます。
- `thumbnail` がない作品は、部屋の色の上に `category` の文字を置いた絵が代わりに出ます。
- 本の表紙のような縦長の画像は、そのままだと上下が大きく切れます。ぼかした背景の上に表紙全体を置いた横長の画像にすると、きれいに収まります（例: `public/works/chara-modeling-book/thumb.webp`）。Claude に頼めば作れます。
- 動画のサムネイルのような 16:9 の画像は、16:10 に切り抜くと左右が少し切れます。端に文字があるときは、上下に余白を足して 16:10 にします（例: `public/works/kcs-cg-movie/thumb.webp`）。
- `alt` には、画像を見られない人向けの短い説明を書きます。

### 外部リンクのボタン（`links`）

- `links` を書いた作品だけ、詳細の本文の下に部屋の色のボタンが出ます。書かなければ、ボタンは出ません。
- 押すと新しいタブで開きます。ボタンの文字は `label` に書きます（例: `'BOOTHで見る'`、`'VRChatで見る'`、`'記事を読む'`）。
- 複数書くと、ボタンが横に並びます。

```ts
links: [
  { label: 'BOOTHで見る', url: 'https://booth.pm/ja/items/5354527' },
  { label: '技術書典で見る', url: 'https://techbookfest.org/...' },
],
```

### 動画（`youtubeId`）

YouTube の URL の `v=` のあとの部分を書きます。

```
https://www.youtube.com/watch?v=dQw4w9WgXcQ  →  youtubeId: 'dQw4w9WgXcQ'
https://youtu.be/dQw4w9WgXcQ                 →  youtubeId: 'dQw4w9WgXcQ'
```

動画がある作品は、詳細のいちばん上がサムネイルではなく動画になります。

## 7. アバター

**ファイル:** `content/avatars.ts`
**モデルの置き場所:** `models/`（`public/models/` ではありません）
**アイコンの置き場所:** `public/characters/`

元の VRM は `models/` に置きます。`npm run dev` や公開のたびに、Web で表示する用に軽くした VRM が自動で `public/models/` に作られます（テクスチャを WebP に変えるだけで、形・ボーン・揺れもの・表情はそのままです）。`public/models/` は自動で作られる場所なので、直接置いたり書き換えたりしないでください。

### アバターを足す

```ts
{
  id: 'timi',                     // 英小文字・数字・ハイフン
  name: 'ティミ',                 // 選択ボタンに大きく出る名前（BOOTH と同じ）
  nameEn: 'Timi',                 // 名前の下に小さく出る英語の名前
  description: 'ゆきうさぎのティミです！', // 選んでいる子のひとこと紹介（選ぶボタンの下に出る）
  badge: '無料配布中',             // 省略できる。紹介の上に出る小さな目印。'制作中' のときは選ぶボタンにも出る
  ogImage: '/avatars/timi-og.png', // 省略できる。共有したときのカードの画像（1200×630）
  booth: 'https://bastelcolor.booth.pm/items/6372032', // 省略できる。「BOOTHで見る」の行き先（省略すると「BOOTH（準備中）」と出る）
  modelUrl: '/models/timi.vrm',  // models/timi.vrm を置くと、この場所で表示される
  icon: {
    normal: '/characters/timi-icon.webp',       // ふだんの顔
    happy: '/characters/timi-icon-happy.webp',  // 選んでいるとき・ホバー中の顔
  },
  brightness: 1.3,                // 省略できる。暗く見えるときに上げる（既定 1）
},
```

- 部屋を開いたときは、**いちばん上のアバター** が最初に表示されます。
- アバターを選ぶと URL が `https://bastelcolor.github.io/avatar/<id>` に変わります（例: `/avatar/quiple`）。この URL を共有すると、その子を選んだ状態で部屋が開きます。X などに貼ったときのカードには、名前・紹介文・`ogImage` の画像が出ます。`id` はなるべく変えないでください。
- `ogImage` は共有したときのカードの画像（1200×630）です。いまの4体は `public/avatars/<id>-og.png` に、トップと同じ空と雲から顔を出す絵を置いています。新しい子の画像は Claude に「〇〇のカード画像を作って」と頼めば作れます。省略するとサイト共通の画像になります。
- 表示用の VRM（`public/models/`）は、サイトを見た人がダウンロードできる状態になります。販売しているモデルを置くときは注意してください。
- `npm run dev` を動かしたままモデルを足したときは、一度止めて動かし直すと表示用の VRM が作られます。
- 白っぽいモデルがくすんで見えるときは `brightness` を 1.2〜1.4 くらいにします。
- スマホなど指で操作する画面では、モデルの向きは動かせません（触れても回らず、画面がスクロールします）。マウスのある画面では、ドラッグでまわせます。

### lilToon の見た目のまま表示する

VRChat 用に lilToon で作ったアバターは、ふつうに VRM に書き出すと MToon に置きかわって見た目が変わります。Unity の **Mochiya Avatar Tools** で書き出すと、lilToon の設定が入った VRM になり、サイトでも lilToon の見た目のまま表示できます（ファーレがこの方法です）。

1. Unity のプロジェクトに Mochiya Avatar Tools を入れる（UniVRM 0.131.2 以降が必要。VCCAvatar_2022 には入れ済み）
2. アバターをシーンに置き、**Mochiya > Avatar Tools** で書き出す。作者名は **Export settings** で Bastelcolor に直しておく
3. 書き出した VRM を `models/` に置き、`content/avatars.ts` のそのアバターに `liltoon: true` を足す

- `liltoon: true` のアバターを選んだときだけ、lilToon を表示するための部品（約310KB）を読み込みます。ほかのアバターやページは重くなりません。
- 同じメッシュを使うオブジェクトが2つあると、書き出しで「An item with the same key has already been added」というエラーになります。非表示のものも含めて、片方をアバターの外に出してから書き出してください。
- 揺れもの（PhysBones）は VRM の揺れものに置きかわり、つかむ・伸ばす・角度の制限は再現されません。

### アイコン画像

- 192×192 の正方形で、顔が真ん中に来る画像にします（丸く切り抜いて表示されます）。
- `normal` と `happy` に同じ画像を指定しても動きます。
- VRM から描画して作ることもできます。そのときは Claude に「〇〇のアイコンを撮って」と頼んでください（他の子と顔の大きさをそろえて撮ります）。

## 8. ブログ

**記事の置き場所:** `content/posts/`（1記事 = 1つの `.md` ファイル）
**記事の画像の置き場所:** `public/posts/<記事のファイル名>/`

### 記事を書く

`content/posts/` に `.md` ファイルを作ります。**ファイル名がそのまま記事の URL になります**（`my-first-post.md` → `/blog/my-first-post`）。ファイル名は英小文字・数字・ハイフンにしておくと安全です。

```md
---
title: 記事のタイトル
date: 2026-10-08
category: 制作メモ
summary: 一覧と、SNS で共有したときに出る一言
thumbnail: /posts/my-first-post/cover.webp
---

ここから本文です。ふつうの Markdown で書けます。
```

先頭の `---` で囲んだ部分（フロントマター）に、記事の情報を書きます。

| 項目 | 必須 | 内容 |
|---|---|---|
| `title` | ○ | タイトル |
| `date` | ○ | 日付（`2026-10-08` の形）。**新しい日付の記事ほど上に並びます** |
| `category` | | カテゴリ。一覧と記事の日付の横に出ます |
| `summary` | | 一覧のタイトルの下と、SNS で共有したときに出る一言 |
| `thumbnail` | | 一覧と記事のいちばん上に出す画像。SNS で共有したときの画像にもなります。ないときは一覧に部屋の色とカテゴリ名が出て、共有の画像はサイト共通の `og.png` になります |
| `draft` | | `true` と書くと公開されません（下書き）。全部の記事が下書きでも大丈夫です（ブログの部屋に「まだ記事はありません」と出ます） |

### 本文で使える書き方

| 書き方 | 表示 |
|---|---|
| `## 見出し` / `### 小見出し` | 見出し（`#` 1つはタイトル用なので使わない） |
| 空行 | 段落の区切り。1回の改行はそのまま改行になります |
| `**太字**` / `*斜体*` | 太字 / 斜体 |
| `- 項目` / `1. 項目` | 箇条書き / 番号付きリスト |
| `[文字](https://...)` | リンク（外部リンクは新しいタブで開きます） |
| `![説明](/posts/記事名/画像.webp)` | 画像 |
| `> 文章` | 引用 |
| `` `コード` `` / ```` ``` ```` で囲む | コード（行内 / ブロック） |
| `\| 見出し \| 見出し \|` | 表 |

サンプルとして `content/posts/hello-new-site.md`（ひと通りの書き方）と `blender-memo.md`（画像なし・表）を置いています。どちらも `draft: true` で非公開にしてあるので、書き方の見本として使ってください（`draft` の行を消すと、手元で表示を確かめられます）。

### 画像

- `public/posts/<記事のファイル名>/` に置いて、`/posts/<記事のファイル名>/画像.webp` のように書きます。
- 横幅 1600px くらいまでの WebP がおすすめです（JPEG・PNG でも表示できます）。
- 縦長の画像は、画面の高さに収まるよう縮んで表示されます。

### 確認

`npm run dev` を動かしたまま `.md` を保存すると、ブログの部屋と記事のページにすぐ反映されます。
記事のページは http://localhost:3000/blog/記事のファイル名 で直接開けます。

## 9. キャラクター画像（雲のうしろ・部屋のすみ）

**ファイル:** `content/pages.ts` の `mascot`
**画像の置き場所:** `public/characters/`

```ts
mascot: {
  normal: '/characters/coflet.webp',        // ふだんの顔（雲のうしろ）
  happy: '/characters/coflet-happy.webp',   // ホバー中と、部屋の右下でのぞく顔
},
```

- 背景が透明な画像を使います。下半分は雲に隠れます。
- 3体とも、**顔の大きさと位置がそろうように** VRM から描画しています。差し替えたり子を増やしたりするときは、Claude に撮影を頼むと、他の子とそろえて作れます。
- しっぽなどが大きくはみ出す子は、画像を右と下に広げて撮り、`width` に「何倍広げたか」を書きます（例: キュイプルは `width: 1.4`）。

## 10. モーション（少し上級）

アバターのビューアでは、VRoid Project の「VRMアニメーション7種セット」の1つ（全身を見せる）をループ再生しています。

**利用規約に関する注意:** https://booth.pm/ja/items/5512385

- `.vrma` ファイルを取り出せる状態で配布するのは禁止です。そのため `.vrma` はそのまま置かず、サイトに埋め込む独自の形式に変換して使っています。
- 商用利用ではクレジット表記が必要です。表記の文言は `content/motions.ts` の `credit` に書いてあり、アバターの部屋に表示されます。

### モーションを差し替える・足す

1. 元の `.vrma` を `motion-sources/` に置きます。このフォルダは git に含まれません。
2. 変換します。

   ```bash
   npm run motion:encode -- motion-sources/ファイル名.vrma モーションID
   ```

   変換結果が `components/vrm/motions/generated/<モーションID>.ts` に出力されます。
3. `components/vrm/motions/index.ts` の `sources` に1行足します。

   ```ts
   'モーションID': () => import('./generated/モーションID'),
   ```

4. `content/motions.ts` の `id` を新しいモーションIDに変えます。

`.vrma` を `public/` に直接置くのは避けてください（規約に反します）。

## 11. 困ったとき

- **画面が真っ白・エラー表示になった**
  直前に保存したファイルの `'` `,` `{ }` `[ ]` の閉じ忘れを確認します。`npm run build` を実行すると、エラーのあるファイルと行番号が表示されます。
- **画像が出ない**
  ファイルの場所と、書いたパスが一致しているか確認します。パスは `public/` を除いて `/` から書きます（`public/works/a/thumb.webp` → `'/works/a/thumb.webp'`）。大文字・小文字も区別されます。
- **保存しても画面が変わらない**
  ブラウザを再読み込みします。それでも変わらないときは、`npm run dev` を止めて、もう一度起動します。
